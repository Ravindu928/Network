What is network security?

Alice wants to mail Bob a letter. Trudy (the intruder) sits somewhere along the route and can read, delete, or slip in letters. Security means four promises.

✉️

Confidentiality

Only Alice and Bob can understand the letter. Alice encrypts, Bob decrypts.

Mail version: a sealed, opaque envelope.

🪪

Authentication

Alice and Bob can each confirm who the other really is.

Mail version: checking the sender's ID card.

🔴

Message integrity

Nobody changed the letter on the way (or afterwards) without it being noticed.

Mail version: an unbroken wax seal.

🏤

Access & availability

The service stays open and usable for real users.

Mail version: the post office isn't jammed with junk.

Cryptography: the secret code room

Alice turns her plaintext m into ciphertext KA(m) with a key. Bob uses his key to get it back: m = KB(KA(m)).

🔐

Mail picture: the algorithm is the lockbox design that everyone knows. The key is the only secret. Security comes from the key, not from hiding how the lock works.

Try it

Write a secret letter (substitution cipher)

A monoalphabetic cipher swaps each letter for another. This is the exact key from the slides. Alice and Bob share it, so it is a symmetric key.

What Trudy sees in the envelope
What Bob reads after decrypting

How would Trudy break it? Brute force means trying all 26! ≈ 4×1026 keys. Statistical analysis is smarter: "e" and "t" are the most common letters, so she looks for the most common cipher letters. If she knows some plaintext (a known-plaintext attack, like knowing the letter is signed "alice"), she learns the pairs for a, l, i, c, e right away. In a chosen-plaintext attack she gets Alice to encrypt text Trudy picked.

A stronger version: n ciphers in rotation

Use n substitution ciphers M1…Mn in a cycle, for example M1, M3, M4, M3, M2, repeat. "dog" uses M1 for d, M3 for o, M4 for g. Now the key is the n ciphers plus the cycle pattern.

Real symmetric standards

DES: 56-bit key, 64-bit blocks, cipher block chaining. A 56-bit key was brute-forced in under a day. 3DES encrypts 3 times with 3 keys.

AES (replaced DES in 2001): 128-bit blocks, 128/192/256-bit keys. If brute-forcing DES took 1 second, AES would take 149 trillion years.

Public key cryptography: the padlock trick

Symmetric keys have a problem: how do Alice and Bob agree on a key if they've never met? Public key crypto fixed this, and it changed a 2,000-year-old field.

🔓
Bob's public key KB+

Like an open padlock Bob hands out to everyone. Anyone can snap it shut on a box addressed to Bob.

🗝️
Bob's private key KB−

The only key that opens Bob's padlock. Bob never shares it. KB−(KB+(m)) = m.

Requirement: given the public key KB+, it must be impossible to work out the private key KB−. The famous algorithm that does this is RSA (Rivest, Shamir, Adleman).

Why is it safe? To find d from the public (n, e), Trudy must factor n into p and q. That's easy for 35 but practically impossible for numbers with 1024-bit primes. Bonus property used later for signatures: KB−(KB+(m)) = m = KB+(KB−(m)). Either order works.

📦

Session keys: RSA is slow (DES is at least 100× faster). So in practice Alice uses RSA once to mail Bob a fresh symmetric session key KS in a padlocked box. After that, they both use KS for the actual letters.

Message integrity, digital signatures & certificates

A digital signature is a wax seal pressed with a signet ring only Bob owns (his private key). Anyone can check the seal with his public key, and nobody can forge it.

1 · Fingerprint (hash)

A hash function H turns any letter into a short, fixed-size message digest H(m). Many-to-one, and you can't build a letter to match a given digest.

2 · Seal (sign)

Signing a whole long letter with a private key is slow, so Bob signs just the fingerprint: KB−(H(m)).

3 · Check the seal

Alice opens the seal with Bob's public key KB+, hashes the letter herself, and compares. Match means it's from Bob and unchanged.

Why the Internet checksum is a bad fingerprint

The checksum is fixed-size and many-to-one, but it's easy to find a different letter with the same checksum. Watch "IOU1 00.9 9BOB" become "IOU9 00.1 9BOB" with the same sum:

Different letters (an IOU for $100.99 vs $900.19), same checksum. Real hash functions: MD5 (128-bit digest, RFC 1321) and SHA-1 (160-bit digest, US standard).

🍕 The pizza prank

Trudy writes "Please deliver four pepperoni pizzas. Thank you, Bob", signs it with her private key, and sends the pizza store her public key claiming it's Bob's. The signature checks out, and Bob gets pizzas he never ordered.

The problem: nobody proved that public key belongs to Bob.

🏛️ Certification Authority (CA)

A CA is like the official post office that stamps your ID. Bob proves who he is to the CA, and the CA issues a certificate: "this public key belongs to Bob", signed with the CA's private key.

To get Bob's key, Alice gets his certificate and checks it with the CA's public key. This also fixes the man-in-the-middle attack on ap5.0.

    TLS: registered mail for every web page

    TLS sits just above TCP and is used by almost every browser and web server (https, port 443). It gives confidentiality (symmetric encryption), integrity (hashing) and authentication (public keys).

    🤝 Handshake

    Alice and Bob use certificates and private keys to check each other and create a shared secret.

    🔑 Key derivation

    The shared master secret (MS) is stretched into a set of keys.

    📨 Data transfer

    Data travels as a series of numbered records, not one big blob.

    🔚 Closure

    Special messages close the connection safely.

    Why four keys?

    Using one key for two jobs is considered bad. So each direction gets its own encryption key and its own MAC key, all made from the master secret.

    Kcencrypt client → server
    McMAC client → server
    Ksencrypt server → client
    MsMAC server → client
    Try it

    Numbered pages: how TLS records stop Trudy

    If the MAC only came at the very end of the stream, nothing could be checked until the connection closed. So TLS splits the stream into records. Each MAC covers the data, the record type and a TLS sequence number. Try Trudy's attacks.

    Records 0–3 carry data (type 0). The last record is type 1: a proper close. Every MAC checks out.

    TLS 1.3 (2018) vs TLS 1.2 (2008)

    A cipher suite is the set of algorithms for key generation, encryption, MAC and signatures. TLS 1.3 offers only 5 choices instead of 37, requires Diffie-Hellman for key exchange, and uses combined "authenticated encryption" for data.

    IPsec: the locked mailbag between branch offices

    IPsec protects every IP datagram (user data and control traffic like BGP and DNS). Picture two branch post offices, R1 and R2, sending sealed mailbags to each other across a dangerous road. That's how a VPN works.

    Try it

    Transport mode vs tunnel mode

    Switch modes to see what gets locked up.

    AH protocol RFC 4302

    Source authentication and integrity, but no confidentiality. A clear plastic mailbag with a tamper seal.

    ESP protocol RFC 4303

    Source authentication, integrity and confidentiality. A locked, opaque mailbag. Used much more than AH.

    Security Association (SA)

    Set up before sending, one per direction. It makes IPsec connection-oriented even though IP is connectionless. Holds the SPI, keys, algorithms and sequence number.

    SPD and SAD

    The Security Policy Database decides whether a datagram uses IPsec. The Security Association Database stores how (the SA state). The SPI in the ESP header tells the receiver which SA to use.

    IKE

    Typing in SAs by hand doesn't scale to hundreds of VPN endpoints. Internet Key Exchange sets them up automatically using a pre-shared secret (PSK) or certificates (PKI), in two phases.

    Wireless security: a new carrier joins the depot

    A phone arriving at a WiFi network is like a new mail carrier showing up at a depot. Before getting the bag keys, they have to prove who they are to head office, and head office has to prove itself too.

    Try it

    802.11 (WiFi) in four phases

    Tap a phase. The cast: mobile device, AP (access point, the depot door) and AS (authentication server, head office).

    WPA3 handshake, step by step

    1. AS makes NonceAS and sends it to the mobile.
    2. Mobile makes NonceM and computes session key KM-AP from both nonces and the shared secret.
    3. Mobile sends NonceM plus an HMAC-signed value built from NonceAS and the shared secret.
    4. AS derives the same KM-AP. Both sides now hold the key without ever sending it.

    Under the hood: EAP (RFC 3748) runs end to end. It's carried as EAPoL over 802.11 between mobile and AP, then over RADIUS/UDP between AP and AS.

    Cellular: 4G LTE vs 5G

    In 4G, the visited network's MME plus the home network's HSS together play the role of WiFi's AS. The mobile's SIM card holds a secret shared in advance with the HSS. The mobile proves itself by computing resM, which must match the HSS's xresHSS. It knows the network is real from the auth_token.

    Firewalls & IDS: the guard at the post office door

    A firewall separates the trusted inside network from the untrusted Internet. It lets some packets in and blocks others. It helps stop denial-of-service (like SYN flooding), illegal access to inside data, and lets only authorized users in.

    Stateless packet filter

    Checks each envelope alone: source/dest IP, source/dest port, protocol, ICMP type, SYN/ACK bits. Fast but heavy-handed.

    Stateful packet filter

    Keeps a logbook of every TCP connection (SYN to FIN). Drops packets that "make no sense", like an ACK for a conversation that never started.

    Application gateway

    Reads the application data too. Example: all telnet must go through the gateway, which checks the user and relays the session.

    Intrusion detection systems (IDS)

    Packet filters only read the outside of the envelope (TCP/IP headers) and treat each one alone. An IDS does deep packet inspection: it opens suspicious parcels and compares the contents to a database of known virus and attack strings. It also connects the dots across many packets to spot port scanning, network mapping and DoS attacks.

    Where the guards stand

    Public servers (web, FTP, DNS) sit in a demilitarized zone (DMZ) between the firewall and the internal network. Several IDS sensors at different spots each do different checks.

    Limits: filters can't detect IP spoofing, each app needs its own gateway, clients must be configured to use the gateway, and UDP is often all-or-nothing. There's always a tradeoff between openness and security.
